# Benchmark result manifest

This directory separates the benchmark records used for the manuscript from
historical and cross-host measurements. Do not replace one record with another:
the manuscript audit names the exact files it reads.

## Manuscript sources

| Record | What it contains | Used for |
|---|---|---|
| `timings.json` | Retained A100 cuDESeq2 timings and corrected one-worker, per-substep R timings for the six real designs. The R `glm_fit` stage is `nbinomWaldTest` plus eligible outlier replacement/refitting and does not repeat the initial dispersion fit. R 4.6.0, DESeq2 1.52.0, apeglm 1.34.0. | GPU columns in Tables 3--4; one-worker per-substep column in Table 4. |
| `r_parallel_a100_12worker.json` | A100-host full-pipeline R timing at one and 12 `MulticoreParam` workers, with standard count-outlier replacement/refitting. R 4.6.0, DESeq2 1.52.0, apeglm 1.34.0. | Both R columns and the best-R speedup in Table 3; the 3.1--13.8x headline. |
| `reference_parity.json` | R--cuDESeq2 output-parity measurements on the six real designs. | Table 2 and numerical-parity claims. |
| `parity.json` | Per-mode eager/graph/Triton differences retained by the A100 run. | GPU-mode agreement claims, including the GTEx maximum absolute dispersion difference. |
| `minmu_counterfactual.json` | Called-set comparison with and without the Wald-covariance `minmu` floor, generated by `bench/minmu_counterfactual.py`. | The `airway_cell` counterfactual in the parity discussion. |
| `../../benchmarks/results_roofline.json` | A100 streaming roof and kernel measurements. | Roofline metrics. |
| `../../benchmarks/results_a100.json` | Gene-axis scaling and graph-capture measurements. | Gene-axis scaling metrics. |
| `../../benchmarks/results_a100_samplesweep.json` | Sample-axis scaling measurements. | Every cell and derived claim in the sample-axis table. |
| `../../benchmarks/results_a100_sweep.json` | CUDA-graph chunk sweep. | Every cell and derived claim in the chunk-ablation table. |
| `TABLES.md` | Rendered summary; never a primary measurement source. | Human-readable benchmark tables. |

The GPU and R worker measurements were collected in separate sessions on the
same A100 host. They are combined only for the end-to-end comparison, and their
provenance remains in the two source files above.

## Historical records (not sources for current real-data claims)

- `../../benchmarks/results_per_step_a100_12core_2026-07-14.json` and
  `../../benchmarks/A100_12CORE_MULTICORE.md` preserve the four synthetic
  A100/12-worker measurements. They used the then-current benchmark revision
  and are the source of the historical 19.3--37.5x synthetic result.
- `r_epyc9b14/` contains a separate CPU-only host sweep. It is useful for
  sensitivity analysis, but its GPU numbers are arithmetic using retained A100
  timings and it is not a same-host benchmark.

## Regeneration rules

1. Regenerate only the R worker record with
   `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 BENCH_R_WORKERS=12 .r46/bin/Rscript bench/run_r_parallel.R`.
   This creates or replaces only `r_parallel_a100_12worker.json`; it does not
   alter GPU timings, parity records, or the R reference cache.
2. Regenerate GPU timings only with the standard GPU benchmark workflow. It
   writes a new `timings.json` and must be accompanied by a refreshed parity
   audit.
3. Run `python bench/render_current_tables.py`,
   `PYTHONPATH=src .venv/bin/python scripts/audit_paper_numbers.py`, and
   `bash scripts/paper_build.sh` after any source measurement changes.
4. Regenerate the `minmu` counterfactual with
   `PYTHONPATH=src .venv/bin/python bench/minmu_counterfactual.py` whenever the
   Wald or independent-filtering implementation changes.

The manuscript audit parses balanced `\fact{...}` markers and requires the set
of marked metrics to equal the set of values recomputed from these artifacts.
Adding an unverified metric or leaving a stale check therefore fails the audit.
