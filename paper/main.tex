\begin{abstract}
\noindent
\textbf{Motivation:} DESeq2 is widely used for bulk RNA-seq analysis. Its
statistical pipeline is rigorous but expensive to repeat at scale because it
fits thousands of gene-level models. We asked whether those fits could run in
parallel on a GPU without changing the analysis.\\[3pt]
\textbf{Results:} We developed \cudeseq, a GPU implementation of the DESeq2
workflow. It processes genes in batches and uses a fused kernel for the most
costly dispersion calculations. Across six real-data designs, its intermediate
estimates and final calls closely matched R~DESeq2~1.52.0. Significant-gene
sets had Jaccard similarity of at least \fact{0.99963}. On one A100, complete
analyses were \fact{3.6--35.1$\times$} faster than 12-worker R. The same
implementation also handled a 2{,}451-sample, six-tissue GTEx model. These
results show that DESeq2-style inference can be accelerated without replacing
it with a different statistical test.\\[3pt]
\textbf{Availability and implementation:} Open source under the MIT license at
\url{https://github.com/synthesizebio/gpu_deseq}; PyTorch and a CUDA GPU are
required for the reported acceleration.\\[3pt]
\textbf{Contact:} maxrhighsmith@gmail.com; greg@synthesize.bio\\[3pt]
\textbf{Supplementary information:} Appended to this manuscript.
\end{abstract}

\section{Introduction}
Differential-expression analysis turns RNA-seq counts into estimates of how
gene expression changes between conditions. DESeq2 \citep{love2014deseq2} is a
common choice for this task. It models count variability, shares information
across genes, limits the influence of outliers, and corrects for multiple
testing. It can also shrink noisy log fold changes (LFCs) with apeGLM
\citep{zhu2019apeglm}. Together, these steps produce stable effect estimates
and calibrated significance calls.

Most of the work is repeated for every gene. Dispersion estimation, GLM
fitting, and LFC shrinkage each solve thousands of small optimization problems.
R~DESeq2 can divide genes among CPU workers, but the calculations remain a good
match for the much wider parallelism of a GPU. The challenge is fidelity.
DESeq2 includes line searches, convergence tests, empirical-Bayes estimates,
and fallbacks for unusual genes. A GPU port must preserve those decisions, not
just the underlying model (Fig.~\ref{fig:schematic}).

This cost matters when the analysis is repeated. Examples include perturbation
screens, resampling studies, many planned contrasts, and evaluation of gene-
expression models. Recent virtual-cell benchmarks sometimes use cheaper
rank-based tests in place of count models
\citep{roohani2025vcc,wei2026perturbench}. Faster DESeq2-style analysis would
make that compromise less necessary. The need is growing alongside foundation
models for gene expression
\citep{theodoris2023geneformer,cui2024scgpt,bunne2024virtualcell,
adduri2025state,koytiger2025gem}.



\begin{figure}[t]\centering
\includegraphics[width=\linewidth]{figures/gpt_schematic.png}
\caption{DESeq2 workflow and its GPU implementation. The upper path shows the
statistical analysis. The lower path shows the two main acceleration ideas:
process genes together on the GPU, and fuse the iterative dispersion fit into
one Triton kernel. CUDA-graph replay provides a third dispersion mode.}
\label{fig:schematic}
\end{figure}

Related tools solve different parts of the problem. glmGamPoi accelerates
Gamma--Poisson GLMs on large sparse matrices \citep{ahlmanneltze2020glmgampoi}.
PyDESeq2 provides a Python implementation with similar, but not identical,
results \citep{muzellec2023pydeseq2}. GPU libraries have also sped up PCA,
neighbor graphs, and clustering in single-cell workflows
\citep{hu2025scalesc}. None of these efforts establishes whether the DESeq2
workflow itself can move to a GPU while retaining close agreement with R.

We address that question with \cudeseq. The implementation uses PyTorch
\citep{paszke2019pytorch} to batch gene-level work. It includes outlier
replacement and apeGLM shrinkage. We also add CUDA-graph
\citep{nvidia2024cudagraphs} and Triton \citep{tillet2019triton} paths for
dispersion estimation. We test agreement at each analysis stage, not only in
the final gene list. We then measure end-to-end performance and GPU memory on
published datasets and nested GTEx cohorts.

\section{Methods}

\subsection{Reference workflow and supported scope}
\label{sec:pipeline}
DESeq2 \citep{love2014deseq2} fits a negative-binomial GLM to each gene. For
gene $g$, let $K_{gi}$ be the count in sample $i$, $s_i$ the sample's size
factor, and $X\in\mathbb{R}^{S\times P}$ the design matrix. The model is
$K_{gi}\sim\mathrm{NB}(\mu_{gi},\alpha_g)$, where
$\mu_{gi}=s_i\exp(x_i^{\!\top}\beta_g)$ and the variance is
$\mu_{gi}+\alpha_g\mu_{gi}^2$.

The workflow has five main stages. It normalizes for library depth, estimates
and moderates dispersion, fits the GLM, tests coefficients, and adjusts for
multiple testing. Optional apeGLM shrinkage stabilizes noisy LFC estimates but
does not change the test p-values. \cudeseq{} preserves this order and passes
the same quantities from one stage to the next.

\subsubsection{Normalization}
\label{sec:normalization}
Median-of-ratios normalization uses GPU reductions and quantiles. As in
DESeq2, \texttt{sfType="ratio"} raises an error when every gene contains a
zero. The \texttt{sfType="poscounts"} alternative supports such sparse
matrices.

\subsubsection{Dispersion estimation}
\label{sec:disp-overview}
Both gene-wise dispersion fits---MLE and MAP---run as batches. Their execution
modes are described in Sec.~\ref{sec:disp}.

\subsubsection{GLM fitting and hypothesis testing}
\label{sec:glm-overview}
Negative-binomial IRLS and the Wald or likelihood-ratio tests are also batched
over genes (Sec.~\ref{sec:glm}).

\subsubsection{Significance filtering and result assembly}
\label{sec:significance}
Cook's filtering, independent filtering, and multiple-testing adjustment use
vectorized operations. In a CUDA run, Cook's distances and count replacement
remain on the GPU. Independent filtering evaluates 50 nested thresholds from a
single p-value ordering. It performs the full Benjamini--Hochberg adjustment
only for the selected threshold. Eligible outliers are then replaced and the
affected genes refitted, as in DESeq2.

\subsubsection{LFC shrinkage}
\label{sec:apeglm-overview}
The apeGLM optimizer runs as a gene batch on the GPU
(Sec.~\ref{sec:apeglm}).

\subsection{Dispersion acceleration}
\label{sec:disp}
The dispersion stage follows DESeq2's \texttt{fitDisp} and
\texttt{estimateDispersions} logic. For each gene, it maximizes the Cox--Reid
adjusted profile log-likelihood
\begin{equation}
\ell_{\mathrm{CR}}(\alpha_g)=\sum_{i=1}^{S}\log \mathrm{NB}\!\bigl(K_{gi};\mu_{gi},\alpha_g\bigr)
\;-\;\tfrac12\log\det\!\bigl(X^{\!\top} W_g X\bigr),
\label{eq:cr}
\end{equation}
where $W_g=\operatorname{diag}\!\bigl(\mu_{gi}/(1+\alpha_g\mu_{gi})\bigr)$.
We retain DESeq2's initialization, line search, trend fit, MAP estimate, and
outlier rule. Dispersion is often the most expensive stage, so \cudeseq{}
provides three ways to run its gradient-ascent loop: eager PyTorch, CUDA-graph
replay, and a fused Triton kernel. They make the same optimizer decisions but
schedule the work differently.

\paragraph{CUDA-graph chunked replay.}
\label{sec:graph}
Eager mode launches several small kernels for each gradient step. The arrays
are only $1$--$10$\,MB, so launch latency can dominate the calculation. CUDA
graphs reduce that overhead by replaying a captured sequence of operations.
Two details require special handling.

First, genes converge at different times. Capturing the full loop would force
every gene to run for the maximum number of iterations. Instead, we capture a
$K{=}10$-iteration chunk and check convergence between replays. State is kept
in persistent buffers. Ten iterations balanced replay overhead against the
extra work done by genes that converge within a chunk.

Second, PyTorch's \texttt{slogdet} and \texttt{solve} synchronize with the host
and cannot be captured. The Cox--Reid term needs both $\log\det(b)$ and
$\operatorname{tr}(b^{-1}\,\mathrm{d}b)$, where $b=X^{\!\top}WX$. We compute
them with an unrolled, no-pivot LU routine. For $P=2\dots6$, it agrees with the
standard \texttt{linalg} path to about $10^{-15}$.

We warm the chunk three times on a side stream before capture. Captured graphs
are cached by tensor shape, chunk length, prior use, data type, and device. The
prior variance is stored in a scalar buffer, so one graph can serve datasets
with different values. Graph mode calls the same arithmetic routine as eager
mode and is therefore bit-identical to it.

\paragraph{Triton full-loop fusion.}
\label{sec:triton}

\begin{figure}[htbp]\centering
\includegraphics[width=\linewidth]{figures/triton_dispersion_schematic.png}
\caption{Fused dispersion estimation in Triton. One program handles one gene.
It loads the counts, fitted means, and design matrix once, then keeps the
gradient-ascent loop inside the kernel. The kernel is used for both gene-wise
fits; the shared trend fit remains outside Triton.}
\label{fig:triton}
\end{figure}

Triton mode launches one program per gene (Fig.~\ref{fig:triton}). The program
loads the gene's counts, fitted means, and design columns once. It then keeps
the likelihood, gradient, and Armijo line search in registers. Each gene exits
when it converges.

Small design matrices are solved directly. We use a closed-form solution for
$P=2$ and unrolled no-pivot LU for $P=3,\dots,6$. The kernel uses fp64
arithmetic. Wider designs fall back to eager mode; the low-level launcher
rejects them rather than silently truncating the model.

After the kernel returns, non-converged and high-dispersion genes receive the
same fallback treatment as in eager mode. Triton changes the floating-point
reduction order and uses its own implementation of \texttt{digamma}. It is
therefore not bit-identical to eager mode. We measure the resulting differences
in Sec.~\ref{sec:parity}. Full pseudocode is given in Supplementary
Algorithms~\ref{alg:triton-overview}--\ref{alg:triton-detail}.

\subsection{GLM acceleration}
\label{sec:glm}
The negative-binomial IRLS solve is batched across genes. Each iteration uses
one batched factorization. Genes that diverge or reach DESeq2's iteration cap
use the reference fallback; only those rows move to the host. Cook's distances,
count replacement, and refitting stay on the GPU. Wald standard errors retain
the $\mu\ge0.5$ floor used by DESeq2, and LRTs use the full--reduced deviance
difference.

\subsection{LFC shrinkage acceleration}
\label{sec:apeglm}
apeGLM \citep{zhu2019apeglm} also optimizes one model per gene. \cudeseq{}
batches its L-BFGS state, line search, and convergence flags. It keeps the
reference initialization and stopping rules, which matter for extreme,
low-count genes with competing posterior modes. As in \texttt{lfcShrink}, only
the coefficient and its standard error are replaced. P-values still come from
the Wald fit.

Several changes reduce repeated work. The loss and gradient share one
gene--sample linear predictor. Terms that do not change during optimization are
computed once. Existing size factors and Wald results are reused. On CUDA,
PyTorch compilation fuses the elementwise work around the matrix products. CPU
execution keeps the eager path.

\subsection{Validation and benchmark design}
\label{sec:parity-method}
We first tested numerical agreement on five simulated fixtures generated with
R~DESeq2~1.52.0. Three use a single-factor design with $P=2$: 12 samples and
200 genes, 30 and 500, and 60 and 2{,}000. A fourth has 60 samples, 1{,}500
genes, and a two-factor design with $P=4$. The fifth has 60 samples, 1{,}000
genes, and a continuous covariate. The respective random seeds are 0, 0, 1, 2,
and 3.

These fixtures test intermediate values throughout the pipeline. They include
size factors; gene-wise, trend, MAP, and final dispersions; GLM coefficients and
fitted means; Cook's distances; Wald standard errors; LRT statistics;
independent filtering; and apeGLM outputs. Single-factor fixtures also test the
local and mean dispersion trends.

We then compared full results on real data. Positive quantities use relative
error; values that cross zero use absolute error. Significant sets use Jaccard
similarity at $\mathrm{padj}<0.05$, and shrunken LFCs use Pearson correlation.
An empty union has Jaccard similarity one. Eager, graph, and Triton modes were
tested separately against the same reference and acceptance thresholds.

Performance was measured on one NVIDIA A100-SXM4-40GB with PyTorch~2.7.1 and
CUDA~12.6. The host had 12 virtual CPUs. The reference used R~DESeq2~1.52.0,
apeglm~1.34.0, and \texttt{MulticoreParam(12)}. Both implementations ran the
ordinary \texttt{DESeq()}, \texttt{results()}, and \texttt{lfcShrink()}
workflow.

GPU results are medians of five synchronized runs after one warm-up. The two
long GTEx CPU endpoints are single cold runs and are reported as endpoint
comparisons. OOM tests are single runs in fresh processes.

The real-data benchmark contains six designs from three published datasets.
Pasilla contributes one- and two-factor designs with seven samples
\citep{brooks2011pasilla}. Airway contributes three design slices with eight
samples \citep{himes2014airway}. GTEx contributes a 300-sample contrast between
whole blood and skeletal muscle at 54{,}922 genes \citep{gtex2020atlas}.

The GTEx counts come from the recount2 reprocessing of SRP012682
\citep{colladotorres2017recount2}. We selected 150 samples per tissue with R
seed 1. Base coverage was divided by each sample's mean read length; missing or
non-positive lengths were set to 100 bases. A separate fixed-seed simulation
varies sample count while holding the gene count at 2{,}000. Nested cohorts
drawn from all 9{,}662 source samples and 54 tissues test larger models.

\label{sec:parity}
We compared each stage of the pipeline with R~DESeq2~1.52.0 across six
real-data designs derived from three datasets (Table~\ref{tab:parity}).
Agreement was evaluated separately for normalization, dispersion estimation,
GLM fitting, significance calls, and LFC shrinkage.

\section{Discussion}
\label{sec:discussion}
\cudeseq{} shows that the DESeq2 workflow can use GPU parallelism without
switching to a different test. It matched R at each pipeline stage and was
\fact{3.6--35.1$\times$} faster end to end. Checking intermediate values was
important. Agreement in the final gene list alone could hide errors in
dispersion, standard errors, or multiple-testing correction.

The useful unit of parallelism is the gene. Basic batching sends thousands of
independent fits to the GPU at once. Dispersion estimation needs more than
batching because it consists of small operations inside variable-length loops.
CUDA graphs reduce launch overhead while preserving eager arithmetic. Triton
goes further by fusing each gene's loop into one kernel. The best choice depends
on the size of the design and the number of samples.

Numerical details matter when matching a reference implementation. The model
equations do not specify every optimizer decision or floating-point operation.
Triton, for example, changes reduction order and supplies its own
\texttt{digamma}. The largest eager--Triton dispersion difference was
\fact{0.2604} on GTEx, compared with at most
\fact{$3.8 \times 10^{-7}$} on the five smaller designs. These differences did
not materially change downstream results in our tests, but Triton is not
bit-identical to eager mode.

GTEx shows both the reach and the present memory limit. The fused path handled
2{,}451 samples and six tissues using about half of a 40-GB A100. Wider eager
models reached the boundary between $P=9$ and $P=10$. Both sample count and
design width increase memory use, so this boundary is specific to the tested
cohorts. Chunking or a wider fused kernel could move it. Either change would
need a new parity analysis.

The strongest use case is repeated analysis: perturbation screens, resampling,
many contrasts, or evaluation of generated expression profiles. For one small
experiment, access to a GPU and added software complexity may outweigh the
time saved. \cudeseq{} is most useful when compatibility with existing DESeq2
analyses matters and the same workflow must run many times.

This study has several limits. All timings come from one A100 and one 12-vCPU
host. Five of the six primary designs have only seven or eight samples, and the
large-scale study uses one GTEx source. Interactions, observation weights,
\texttt{ashr}, normal shrinkage, and the \texttt{glmGamPoi} dispersion backend
were not validated. Triton supports $P=2,\dots,6$; wider designs use eager
dispersion. The large-GTEx CPU endpoints and OOM probes are single observations.

Within this scope, gene-batched GPU execution preserves DESeq2-style results
while cutting analysis time. It offers a practical alternative to replacing a
count model with a cheaper surrogate in high-throughput settings.

\section*{Supplementary benchmark details}
The benchmark host was a KVM virtual machine with a 2.20-GHz Intel Xeon CPU,
6 physical cores, 12 logical CPUs, 83\,GiB RAM, and Linux~5.10. GPU runs used
one NVIDIA A100-SXM4-40GB. The software stack was PyTorch~2.7.1, CUDA~12.6,
and NVIDIA driver~580.126.20. The R stack was R~4.6.0, DESeq2~1.52.0, and
apeglm~1.34.0.

OMP, OpenBLAS, and MKL were pinned to one thread per R worker. Main-suite and
real-GTEx GPU values are medians of five runs after one warm-up. The two large
GTEx CPU endpoints and four OOM probes are single runs. The synthetic sample
sweep uses seven measurements after three warm-ups.
